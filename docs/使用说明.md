# 使用说明

这个博客基于 [Astro](https://astro.build/) + [Fuwari](https://github.com/saicaca/fuwari)，
部署目标是 GitHub Pages：`https://riverwind1024.github.io/`。

## 目录速查

| 路径 | 作用 |
|---|---|
| `src/content/posts/` | 所有文章（Markdown） |
| `src/content/spec/about.md` | 「关于」页面的内容 |
| `src/config.ts` | 站点标题、副标题、导航栏、头像、社交链接、主题色 |
| `src/styles/variables.styl` | 配色、字体、圆角等样式变量 |
| `public/` | 静态资源（favicon、导入文章时复制的图片） |
| `scripts/import-markdown.mjs` | Markdown 导入工具 |
| `.github/workflows/deploy.yml` | 推送到 main 后自动部署到 GitHub Pages |

## 本地开发

```bash
pnpm install
pnpm dev        # http://localhost:4321
```

其他常用命令：

```bash
pnpm build      # 构建到 dist/（含 Pagefind 搜索索引）
pnpm preview    # 预览构建结果
pnpm check      # TypeScript / Astro 类型检查
pnpm lint       # Biome 格式化 + 检查
```

## 文章是怎么编译成页面的

`pnpm dev` 或 `pnpm build` 时，Astro 会扫描 `src/content/posts/`（**含所有子目录**）下的
`.md` / `.mdx` 文件，每个文件都会按 `src/pages/posts/[...slug].astro` 这个模板生成一个静态页面，
**不需要手动注册路由、不需要改任何配置**。

| 你做的操作 | 会发生什么 |
|---|---|
| 在 `src/content/posts/` 新建或修改 `.md` | `pnpm dev` 下自动热更新，浏览器里马上能看到 |
| 执行 `pnpm build` | 全量编译到 `dist/`，同时生成搜索索引和 RSS |
| `git push` 到 `main` | GitHub Actions 自动执行 `pnpm build` 并发布到线上 |

### 文件必须满足的规则

1. **位置**：必须放在 `src/content/posts/` 里，子目录可以，例如 `src/content/posts/tech/astro.md`
2. **frontmatter**：文件开头必须有 `---` 包起来的元信息，其中 `title` 和 `published` 是必填项
3. **日期格式**：`published: 2026-11-17`，**不要加引号**（加引号会变成字符串，构建报错）
4. **草稿**：`draft: true` 的文章只在 `pnpm dev` 下可见，不会被发布
5. **文件名决定 URL**：
   - `hello-world.md` → `/posts/hello-world/`
   - `tech/astro.md` → `/posts/tech/astro/`
   - `notes/index.md` → `/posts/notes/`

最小的可用文章长这样：

```markdown
---
title: 标题
published: 2026-11-17
---

正文。
```

不满足上面的规则时 `pnpm build` 会直接失败，而不是悄悄跳过，常见报错见文末的「常见问题」。

### 能不能直接放别的文件夹？

默认不行，内容目录是写死的 `src/content/posts/`。有两种替代做法：

- 用导入工具把文件搬进来（推荐）：`pnpm import:md ~/你的文件夹/`
- 或者把整个文件夹复制到 `src/content/posts/` 下，当作子目录使用

## 写一篇新文章

```bash
pnpm new-post 文章文件名
```

会在 `src/content/posts/` 下生成一个带 frontmatter 骨架的文件。字段说明：

```yaml
---
title: 文章标题
published: 2026-11-17        # 必须是 YYYY-MM-DD，不要加引号
updated: 2026-11-20          # 可选
description: 首页卡片上的摘要
image: ./cover.jpg           # 可选，封面图
tags: [标签1, 标签2]
category: 分类
draft: false                 # true 时只在本地可见
lang: zh_CN                  # 可选，不写则跟随站点语言
---
```

文件名即 URL 的一部分：`hello-world.md` → `/posts/hello-world/`。

## 从别处导入 Markdown

支持单个文件或整个目录（递归），兼容 Obsidian、Hexo、Hugo、Jekyll 等常见 frontmatter 写法。

```bash
# 导入一个目录
pnpm import:md ~/Documents/旧文章/

# 导入单个文件，并指定分类和标签
pnpm import:md ./note.md --category 随笔 --tags 读书,笔记

# 先看看会发生什么，不写文件
pnpm import:md ./note.md --dry-run
```

选项：

| 选项 | 说明 |
|---|---|
| `--slug <name>` | 指定输出文件名（仅单文件导入时有效） |
| `--category <name>` | 指定分类，覆盖原文 |
| `--tags <a,b>` | 追加标签 |
| `--draft` | 导入为草稿 |
| `--no-images` | 不复制本地图片 |
| `--force` | 覆盖同名文章 |
| `--dry-run` | 只打印结果，不写文件 |

脚本会自动做这些事：

- 字段映射：`date` / `pubDate` / `created` → `published`，`summary` / `excerpt` → `description`，
  `categories` → `category` 等
- 没有标题时用正文首个 `# H1`，并从正文中移除（避免和页面标题重复）
- 没有摘要时截取正文前 120 字
- 没有日期时用文件的修改时间
- 转换 Obsidian 语法：`[[双链|别名]]` → 别名，`![[图片.png]]` → 图片，`==高亮==` → 加粗
- 把本地图片复制到 `public/imported/<slug>/`，并把引用改写成绝对路径
- 目标文件重名时自动追加 `-2`、`-3`，不会覆盖已有文章

> 注意：导入只做语法层面的转换，不保证排版和原来完全一致。导入后建议本地 `pnpm dev` 扫一眼。

## 改站点信息

编辑 `src/config.ts`：

- `siteConfig.title` / `subtitle` / `lang`
- `themeColor.hue`：0 红、200 青、250 蓝、345 粉（调色盘在页面侧栏也能实时改）
- `navBarConfig.links`：导航项
- `profileConfig`：头像、昵称、简介、社交链接

改配色和字体去 `src/styles/variables.styl`，所有颜色都通过 CSS 变量定义。

## 评论

评论区用 [giscus](https://giscus.app/zh-CN)，数据存在本仓库的 **Discussions** 里，
不依赖任何第三方数据库，也没有广告和追踪。

配置在 `src/config.ts` 的 `commentConfig`：

```ts
export const commentConfig: CommentConfig = {
	enable: true,                    // 设为 false 可关闭评论
	repo: "RiverWind1024/RiverWind1024.github.io",
	repoId: "R_kgDOVxW9jw",          // 仓库的 node_id
	category: "Announcements",       // 存放评论的 Discussion 分类
	categoryId: "DIC_kwDOVxW9j84DLUa3",
	mapping: "pathname",             // 按页面路径关联 discussion
	lang: "zh-CN",
};
```

组件是 `src/components/Comments.astro`，在文章页 `src/pages/posts/[...slug].astro`
的版权信息之后引入。

### 首次使用要装 App

访客要能用 GitHub 账号评论，需要先在仓库上安装 giscus App：

1. 打开 https://github.com/apps/giscus
2. 点 **Install**，选择 `RiverWind1024.github.io` 仓库
3. 回到博客任意文章页，评论区应该能正常加载

如果评论区显示「giscus 未安装」或加载失败，先检查这一步。

### 两个实现细节

1. **swup 无刷新跳转**：Fuwari 用 swup 做页面过渡，点链接不会真正刷新页面，
   页面内的 `<script>` 不会重新执行。所以评论加载器放在 `src/layouts/Layout.astro`
   末尾只初始化一次，然后监听 `astro:page-load` 事件，在每次切换页面后重新挂载。
2. **深浅色同步**：通过 `MutationObserver` 监听 `<html>` 的 class 变化，
   用 giscus 的 postMessage API 把主题同步到 iframe，避免站内切深色后评论区还是白的。

### 换成别的仓库

改了 `repo` 之后，`repoId` 和 `categoryId` 也要一起换：

```bash
# 仓库 ID
gh api repos/<owner>/<repo> --jq .node_id

# 分类 ID（先启用 Discussions）
gh api graphql -f query='query {
  repository(owner:"<owner>", name:"<repo>") {
    discussionCategories(first:10) { nodes { id name } }
  }
}'
```

## 部署到 GitHub Pages

**当前仓库已经配置完成**，日常发布只需要 `git push` 到 `main`。

如果要从零再搭一个同样的站点，需要三步：

1. 在 GitHub 新建仓库，名字必须是 **`RiverWind1024.github.io`**
   （用这个名字，站点在根路径，不需要配置 `base`；用别的名字则要改 `astro.config.mjs` 的 `base`）
2. 推送代码：

   ```bash
   git init
   git add -A
   git commit -m "init blog"
   git branch -M main
   git remote add origin git@github.com:RiverWind1024/RiverWind1024.github.io.git
   git push -u origin main
   ```

3. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**

之后每次 `git push` 到 `main`，Actions 会自动构建并发布，通常 1～2 分钟后可访问。
在仓库的 **Actions** 标签页可以看构建日志。

### 换成别的仓库名

如果仓库不叫 `RiverWind1024.github.io`，站点地址会变成
`https://riverwind1024.github.io/<仓库名>/`，需要改两处：

```js
// astro.config.mjs
site: "https://riverwind1024.github.io",
base: "/<仓库名>",
```

Fuwari 内部的导航链接会自动带上 `base`，但你自己在文章里写的站内绝对链接
（以 `/` 开头）不会，需要手动加上前缀。

## 常见问题

**构建报 `title: Required` / `published: Required`？**
文章缺少必填的 frontmatter 字段。补上 `title` 和 `published` 即可；也可以先用
`pnpm import:md <文件>` 导入，脚本会自动补全。

**构建报 `published: Expected type "date", received "string"`？**
frontmatter 里的日期被加了引号。写成 `published: 2026-11-17`，不要写成 `"2026-11-17"`。
`pnpm import:md` 生成的文件不会有这个问题。

**文章放进去了，但页面没出现？**
先确认三件事：文件在 `src/content/posts/` 下、扩展名是 `.md`/`.mdx`、frontmatter 合法。
如果 `pnpm dev` 没报错但页面 404，重启一下 dev server。

**改了文章，线上没变化？**
`git push` 只是触发构建，还要等 Actions 跑完（约 1～2 分钟）。到仓库的 **Actions** 页
确认最新的 Deploy 是绿色。另外浏览器可能缓存了旧页面，强制刷新试试。

**文件名能用中文吗？**
可以，URL 会被编码成 `%E4%B8%AD%E6%96%87` 这种形式，能正常访问但不美观。
想要干净的 URL，用英文文件名，标题仍然可以是中文。

**改完配置不生效？**
先停掉 `pnpm dev` 再重启。`src/config.ts` 不是所有字段都能热更新。

**图片不显示？**
`image` 和正文图片有三种写法：`https://...` 外链、`/xxx.png` 指向 `public/` 目录、
相对路径（相对 md 文件所在目录）。导入工具统一用 `/imported/<slug>/` 这种绝对路径。

**搜索搜不到新文章？**
搜索索引是 `pnpm build` 时由 Pagefind 生成的，`pnpm dev` 下用的是旧索引，构建后才会更新。

**想同步上游 Fuwari 的更新？**

本仓库是从 Fuwari 复制后重新初始化 git 的，和上游没有共同历史，直接合并需要额外参数：

```bash
git remote add upstream https://github.com/saicaca/fuwari.git
git fetch upstream
git merge upstream/main --allow-unrelated-histories
```

因为本项目已经改动过 `src/config.ts`、`astro.config.mjs`、文章页和布局文件，冲突会比较多，
一般只挑需要的 commit 来看更省事：

```bash
git log upstream/main --oneline          # 看上游改了什么
git show <commit>                        # 看具体改动，手动应用
```
